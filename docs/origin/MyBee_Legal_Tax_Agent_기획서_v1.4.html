2.1 규제 쟁점

규범쟁점설계에 주는 제약
변호사법 제109조변호사가 아닌 자가 금품 등을 받고 법률사무(법률상담·법률관계 문서 작성 등)를 취급하면 처벌 대상이다. 유료 SaaS가 타사의 구체적 사안에 법률판단을 제공하면 쟁점이 된다.플랫폼 운영사는 의견의 발행 주체가 되지 않는다. 의견은 테넌트 내부 조직 또는 테넌트가 선임한 자격자의 업무 보조 산출물이다.
2025 리걸테크 판결(로폼 사건 보도)이용자 입력에 따라 표준 양식을 채우는 서비스는 "구체적 사안에 대한 법률적 판단이나 개입이 없는 단순 양식 제공"으로 법률사무가 아니라고 보았다. 반면 생성형 AI가 개별 상황에 법률판단을 가미하거나 유료 변호사 검토와 연계하면 위법 소지가 있다고 언급되었다.MyBee Legal Agent는 개별 사안 판단을 하므로 양식 제공 논리로 면책되지 않는다. 따라서 사용자·발행 주체 제한이 필수다.
변호사법 제34조변호사가 아닌 자와의 동업·알선 등을 제한한다.플랫폼 안에서 외부 변호사·세무사 매칭·연계·수수료 구조를 두지 않는다. 자격자는 테넌트가 직접 등록한다.
세무사법(세무대리)타인의 세무 신고·조정·의견 제공은 세무대리 자격 영역이다.세무 의견 승인은 세무사·공인회계사 등 자격자 또는 테넌트 자신의 내부 결정으로 한정한다. 신고서 제출은 TA 경유 + 사람 승인(설계지시문 제6.7.2조).

권위(얼마나 믿을 만한가)와 구속력(누구를 구속하는가)은 다른 축이다. v1.0은 두 축을 한 등급에 섞었다.

B1조세심판원·감사원·국세청 불복 결정, 기획재정부 세법해석(예규), 법제처 법령해석불복 결정은 해당 사건 과세관청을 기속. 일반 사안에는 설득 권위.

9.2 조문 버전 — 명세 통일 V-24 V-25

v1.0의 8장 LAW_VERSION과 19장 statute_version을 lgsrc.statute_version 하나로 통일했다. 전체 컬럼 명세는 21장에 있다. next_version_id는 previous_version_id와 이중으로 관리하면 불일치가 생기므로 삭제하고, 다음 버전은 조회로 도출한다.

-- 기준일 d 에, 인지시점 k 에 알고 있던 조문 버전
SELECT *
  FROM lgsrc.statute_version
 WHERE law_id = :law AND provision_key = :key
   AND effective_from <= :d AND (effective_to IS NULL OR effective_to >= :d)
   AND recorded_from  <= :k AND (recorded_to  IS NULL OR recorded_to  >  :k);

9.4 실제 개정 예시 V-13

상법 제382조의3(이사의 충실의무)은 2025-07-22 시행 개정으로 충실의무 대상에 '주주'가 명시되고 총주주 이익 보호·공평 대우 의무가 추가되었다. 이사회 결의일이 2025-03-14인 사안과 2025-09-01인 사안은 인용할 조문 버전이 다르다. 시점을 묻지 않고 현행 조문을 인용하면 전자의 의견이 틀린다.
예시는 설계 설명용이며, 시스템은 적재된 원문과 부칙으로만 판정한다.
필수 규칙. T-01 사건 사실의 기준일이 있으면 현행법을 자동 적용하지 않는다. T-02 기준일이 없으면 Fact Agent가 "현재 기준"과 "거래 당시 기준" 중 무엇이 필요한지 판정하고, 판정할 수 없으면 사실 보완 질의를 한다. 그래도 불명확하면 가정으로 명시하고 확신도의 fact_completeness를 낮춘다. T-03 부칙 규칙이 DRAFT인 조문에 의존한 핵심 주장은 temporal_check=REVIEW로 둔다.

11.1 검색 원칙

  • 법률 검색은 단일 embedding similarity로 끝내지 않는다.
  • 권한·테넌트·기준일 필터는 검색 전에 건다. 검색 후 걸러내면 권한 밖 문서가 점수·요약·캐시에 흔적을 남긴다. v1.0 그림의 Temporal 병렬 검색기와 후단 Date Filter 이중 표기를 이 원칙에 맞춰 정리했다.
  • 기준일 사전필터는 유효기간 겹침만 본다. 부칙 적용 여부는 결정론적 규칙이므로 후단 Temporal Validator가 판정한다.
  • 사건번호·조문번호·문서번호처럼 정확도가 중요한 것은 lexical/BM25와 번호 직접 조회를 우선한다.
  • 유사 사실관계는 dense vector + reranker, 법리 연결은 graph traversal.
  • 최종 Context는 "문서 Top-K"가 아니라 쟁점별 Evidence Pack이며, 지지 근거와 반대 근거를 함께 담는다.
  • 의미 캐시 키에는 질의 해시와 함께 권한 범위 해시와 원문 스냅샷을 넣는다.

13.3 Confidence는 하나의 숫자로 만들지 않는다 V-31

v1.0 예시는 contrary_authority_risk만 "높을수록 나쁨"이어서 나머지와 방향이 반대였다. 모든 항목을 0~1, 높을수록 좋음으로 통일한다.

confidence = {
  evidence_completeness:        0.98,   // MATERIAL 주장 중 근거 연결 비율
  citation_integrity:           1.00,   // 결정론 검사 통과 비율
  temporal_fit:                 0.96,
  fact_completeness:            0.82,   // 가정·미확인 사실이 결론에 미치는 정도의 역
  interpretation_agreement:     0.88,   // 교차검증 EA 간 일치

21.1 공통 규약

  • 모든 테이블 끝에 created_at timestamptz NOT NULL DEFAULT now(), ext jsonb NOT NULL DEFAULT '{}'를 둔다. 운영 중 속성 추가는 ALTER TABLE 없이 ext + 필드 메타데이터로 흡수한다(Zero-DDL).
  • MyBee 공통 컬럼 15개 채택 v1.3 — MyBee 플랫폼에 탑재할 때 lg* 23표는 DB 테이블설계서 v3.2 제7.3 의 공통 컬럼 15개(tenant_id · created_at · created_by · created_actor · updated_at · updated_by · deleted_at · is_deleted · row_version · trace_id · schema_ver · source_system · ext · updated_actor · deleted_by)를 그대로 갖는다. 21.2 · 21.3 의 컬럼 수(23표 · 310컬럼)는 이 문서 고유 컬럼 + 공통 컬럼 중 created_at · ext 2개로 센 값이며 나머지 13개는 명세에 되풀이하지 않는다. lgmat 10표는 명세에 이미 있는 tenant_id(uuid NOT NULL)가 공통 컬럼과 같은 컬럼이므로, 공통 컬럼을 모두 넣은 물리 컬럼 수는 310 + 23×13 − 10 = 599이다. 공용 표(lgsrc · lgeval)의 공통 tenant_id는 플랫폼 예약 테넌트 값만 가지며 mbcore.platform_asset에 등재한다 — 테넌트 자료 컬럼이 아니므로 21.4 S9 판정은 그대로다. 추가 전용 표(agent_step_log)는 논리 삭제가 금지되어 deleted_at · deleted_by가 항상 NULL 이다. 고유 컬럼 중 공통 컬럼과 이름이 겹치는 것은 없다(빌드에서 대조 — v1.3 에서 matter_fact.source_system을 source_domain으로 개명).
  • 코드 컬럼은 가변 길이 v1.3 — matter.work_code varchar(20) · matter.project_code varchar(30). 업무코드 · 프로젝트 코드의 자릿수 · 세그먼트 구성 · 검증식은 코드 체계(mbcode.code_scheme) 데이터가 정하며, 고객사가 구성을 바꿔도 DDL 이 생기지 않는다(설계지시문 제4.7.1조, 플랫폼 표와 같은 타입).
  • 열거형은 CHECK 제약으로 강제하며, 열거값 길이는 컬럼 길이 안에 있음을 정적 검사로 확인했다(21.4장 S6).
  • 복합 UK에 들어가는 컬럼은 NOT NULL로 둔다. "전체"를 뜻하는 값은 NULL 대신 'ALL'·'NONE' 같은 명시값을 쓴다.
  • Platform2 대응 열은 MyBee Platform2 스키마와 연결할 위치다. 실제 결합 방식(확장 테이블 vs 뷰)은 27장 O-06에서 결정한다.

23.1 권한

  • V-16 v1.0의 "프로젝트·법인·국가·직급·직무 기준 ABAC"에서 직급을 삭제했다.   • V-43 v1.0의 "외부 LLM 사용 시 Matter별 데이터 반출정책을 Trust Agent가 확인"은 삭제했다. Local LLM이 기본이고, 외부 모델 호출이 필요하면 VA 반출 규칙 판정 후 TA가 호출한다(반출 규칙은 판정 기준 목록 등재 · 판 승인 · 정책 묶음 게시로만 변경 — 6.1, v1.3). LAWYER_SECRET·PERSONAL_DATA 사안은 외부 모델 호출 규칙에서 기본 거부한다.
