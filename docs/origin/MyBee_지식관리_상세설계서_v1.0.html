용어 정의 — 이 문서에서 쓰는 말

「버전」은 버전, 데이터베이스의 표는 DB Table, 「중복 실행 방지」은 중복 실행 방지로 부른다(설계지시문 19.1.4).

버전 (version)문서 · 기준 · 정의가 고쳐질 때마다 매기는 번호. v1.0 → v1.1 처럼 올라간다. 예전 문서에서 「버전」이라고 부르던 것을 이 문서부터 버전으로 부른다.옛 버전은 고치지 않고 그대로 두고 새 버전을 따로 낸다. 그래야 그때 무엇을 보고 결정했는지 나중에 되살릴 수 있다.
DB Table데이터베이스에 실제로 만들어지는 표. 예) mbproj.project_request. 예전 문서에서 그냥 「표」라고 부르던 것을 DB Table 로 부른다.문서 안에서 읽으라고 그린 표(비교표 · 목록표)는 그대로 「표」라고 부른다. 둘을 섞지 않는다.
중복 실행 방지 (idempotency)같은 요청이 두 번, 세 번 들어와도 결과가 한 번 처리한 것과 똑같게 만드는 성질. 예를 들어 신청서 제출 버튼을 두 번 눌러도 신청은 하나만 생기고, 통신이 끊겨 시스템이 같은 요청을 다시 보내도 돈이 두 번 나가지 않는다.왜 필요한가 — 네트워크는 끊기고, 시스템은 답이 없으면 다시 보내고, 사람은 버튼을 두 번 누른다. 이 세 가지는 막을 수 없으므로 두 번 와도 안전하게 만든다.
중복 실행 방지 키 (중복 실행 방지 키)같은 요청인지 가리는 열쇠. 이 열쇠가 같으면 새로 처리하지 않고 먼저 처리한 결과를 그대로 돌려준다. 예) 프로젝트 신청의 열쇠는 「회사 + 신청번호 + 개정차수」다 — 같은 신청서를 두 번 보내도 신청은 하나다.열쇠는 업무적으로 뜻이 있는 값으로 만든다. 시각 · 난수 · 재시도 횟수 · 서버 이름처럼 매번 달라지는 값은 넣지 않는다. 넣으면 두 번째 요청이 「다른 요청」이 되어 중복이 생긴다.
되돌릴 수 없는 일 (non-idempotent)이체 · 발송 · 신고처럼 한 번 나가면 되돌리기 어려운 일. 이런 단계는 중복 실행 방지 키를 반드시 두고, 답이 없으면 다시 보내지 않고 조회해서 결과를 확인한다.답이 없는 상태를 「모름」으로 두고 사람이 확인하게 한다. 다시 보내는 것이 가장 위험하다.
업무코드회사의 일을 더 쪼갤 수 없는 단위로 나눠 붙인 코드. 예) FL0012001 프로젝트 신청. 사람이 하든 에이전트가 하든 같은 코드로 부른다.모든 일은 업무코드로 수행되고, 보상 · 원가 · 기록이 모두 이 코드에 붙는다.
업무영역업무코드를 묶는 큰 분류. D01 HW개발 … D18 감사 · D19 프로젝트기획·생성 · D20 지식관리(2026-09-29 신설) — 모두 20개.코드 안의 두 자리(FL0019001)가 업무영역이다.
스킬 · 도구 · 규칙업무코드를 수행하는 세 가지 수단. 스킬은 AI 가 문장을 읽고 쓰는 일, 도구는 계산 · 서식 · 외부 연결처럼 정해진 대로 도는 프로그램, 규칙은 조건과 결론을 표로 적어 둔 판정.수치와 판정은 도구와 규칙이 한다. AI 는 수치를 만들지 않는다.
PA · IA · EA · TA · VAPA 는 프로젝트를 맡는 에이전트(프로젝트 1개에 1개), IA 는 사람의 말을 알아듣고 업무로 잇는 에이전트, EA 는 법무 · 회계 같은 전문가 의견을 내는 에이전트, TA 는 외부 시스템을 부르는 에이전트, VA 는 결과를 검증하는 에이전트.외부로 나가는 일은 TA 만 한다.
자율 수준 L1 · L2 · L3에이전트가 사람 없이 어디까지 갈 수 있는지. L1 은 사람이 결정, L2 는 에이전트가 하되 사람이 승인, L3 는 에이전트가 하고 사람은 나중에 본다.위험이 큰 업무일수록 낮은 수준을 쓴다.
NVT 토큰업무를 수행하면 쌓이는 회사 안의 점수. 연말에 단가를 곱해 인센티브 · 연봉에 반영된다.직책이 아니라 수행한 업무에 붙는다.
채택 보상금제안이 채택되었을 때 제안자에게 한 번 주는 보상. 직원은 토큰으로, 외부 제안자는 현금으로 받는다. 상한 500만 원.가결(직원) 또는 용역 계약 체결(외부) 때 지급한다.
사업화 성과 보상제품 · 서비스가 실제로 팔린 뒤 해마다 나누는 보상. 연간 순매출의 0 ~ 3% 안에서 위원회가 정한다.제안 20% · 원 기여 30% · 진행 기여 50% 로 나눈다. 진행 기여는 해마다 다시 계산한다.
판정 기준 버전문턱 값 · 요율 · 가중치처럼 나중에 바뀔 수 있는 숫자를 화면이나 규칙 본문에 박지 않고 따로 모아 둔 것. 예) PRJ-ECON(경제성) · PRJ-RESEARCH(조사) · PRJ-REWARD(보상).값이 바뀌면 새 버전을 게시하고, 지난 판정은 그때 버전으로 다시 볼 수 있다.
개정차수한 신청서를 고쳐 다시 낼 때 올라가는 번호. 제출한 개정차수는 고치지 않고 새 개정차수를 만든다.중복 실행 방지 키의 한 조각이기도 하다.
관리 최소집합모든 프로젝트에 반드시 담기는 D12 업무코드 5건(개설 · 업무 구성 확정 · PM 지정 · 진행 보고 집계 · 종결).빼거나 바꿀 수 없다.
게이트다음 단계로 넘어가려면 통과해야 하는 관문. 이 문서에서는 G-1 등재 · G0 아이디어 · G1 기획 · G2 신청 · G3 심의 · G4 착수.게이트마다 무엇을 확인하는지 정해 둔다.
사전 조사신청 전에 에이전트가 하는 조사. 시장 조사(시장 규모 · 경쟁 동향)와 소요 비용 조사(개발 기간 · 단계별 비용) 두 가지다.조사는 에이전트가 하고, 채택은 사람이 승인한다.
TAM · SAM · SOM시장 크기를 세 겹으로 본 것. TAM 은 품목 전체 시장, SAM 은 우리가 닿을 수 있는 시장, SOM 은 실제로 가져올 수 있는 몫(하단 · 상단).편익의 판매 수량은 SOM 하단을 기본으로 쓴다.

1. 결론

한 줄. 지식은 원장으로 다룬다 — 누가 소관하고, 어느 버전이 언제부터 언제까지 적용되며, 누구에게 열리는지가 행으로 남는다. 그 위에 온톨로지(개념 · 관계)를 사람이 확인해 얹고, 검색은 형태소 · 벡터 · 관계 확장을 한 PostgreSQL 안에서 권한 칸과 같은 행으로 건다. 판정은 식별자 조회만 한다.

6. 법령 · 기준서 · 해석 — 수명주기와 이중 시간

적재. 자료원 등록(004) → 이용 허락 판정(005) → 원문 조회(CN-31 법령 정보 · CN-40 기준서 제공처) → 문서 구조 파서(TL-48)가 조 · 항 · 호 · 목 · 단서 · 부칙 · 별표를 나눠 조문 식별자(말뭉치 + 버전 + 조항호)를 부여 → 원문 해시 · 조문 수 · 시행일 대조(규칙) → 기록. 「현행」 하나만 들여오지 않는다 — 과거 사건을 보려면 연혁과 부칙이 필요하다.

이중 시간. 모든 버전 · 조문 · 절은 적용 기간(valid_from · valid_to)과 기록 시각(recorded_at)을 따로 갖는다. 시점 조회는 「사건일 T 에 적용되던 조문을, 판정일 R 에 우리가 알던 대로」 두 축으로 한다. 적용 기간을 모르면 NULL 이 아니라 valid_unknown 을 켠다 — NULL 을 「항상 적용」으로 읽는 사고를 막는다. 날짜만으로 적용을 확정하지 않는다 — 경과조치 · 소급 · 행위 유형은 EA 의견과 사람 확인으로 본다.

-- 사건일 :t 에 적용되던 조문을, 판정일 :r 에 기록되어 있던 대로(판정 재현)
SELECT c.clause_ref, c.body_text, c.effective_from, c.effective_to
  FROM mbknow.clause c
 WHERE c.corpus_code = :corpus AND c.article_no = :art
   AND c.effective_from <= :t AND (c.effective_to IS NULL OR c.effective_to > :t)
   AND c.recorded_at <= :r
 ORDER BY c.recorded_at DESC LIMIT 1;

7. 온톨로지 — 첫 스키마

아래 개념 유형 · 관계 유형은 첫 값이다. 온톨로지 스키마 확정(FL0020002)이 버전으로 굳히고, 운영하면서 거절된 후보가 몰리는 곳을 보고 고친다. 관계 유형은 적을수록 좋다 — 새 유형은 기존 유형으로 표현이 안 될 때만 더한다.

SUPPLEMENTS보충 적용LAW_DOC → LAW_DOCNEVER0특별법에 없는 사항 — 확장하지 않고 표시만
SUPERSEDES대체한다PROVISION → PROVISIONNEVER0개정 전후 — 시점 조회가 쓴다(확장 아님)
BASIS_OF근거이다PROVISION · SECTION → RULEON_DEMAND1법령 · 사규 조문이 실행 규칙의 근거(regulation_rule_link 와 같은 뜻)
SUPERIOR_TO상위 규범이다PROVISION → SECTIONON_DEMAND2법령 → 규정 → 규칙 → 세칙 → 지침(추이)
IMPOSES부과한다PROVISION · SECTION → OBLIGATION · PROHIBITIONON_DEMAND1조문이 의무 · 금지를 정한다

HAS_THRESHOLD기준값을 갖는다OBLIGATION · PERMISSION → THRESHOLDALWAYS1기준값은 판정 규칙의 파라미터로 이어진다

SAME_AS같은 뜻TERM → TERMALWAYS1영역 간 같은 개념 — 이름이 달라도

법령 관계는 모두 출처 의무(requires_source)가 있다. 파서가 뽑는 것 — DEFINES_TERM_FOR · EXCEPTION_TO · APPLIES_MUTATIS_MUTANDIS · DELEGATES_TO · CITES · SUPERSEDES(문언 규칙). AI 가 후보로 내는 것 — IMPOSES · APPLIES_TO · PERFORMED_BY · SAME_AS · BROADER_THAN 등 해석이 필요한 관계. 후보는 확신도 순으로 사람이 확인한다(FL0020027).

8. 지식 그래프와 검색 — PostgreSQL 안의 GraphRAG

8.1 왜 Neo4j 가 아닌가 — 대안 비교

대안얻는 것잃는 것판단
A. 벡터만구현이 간단하다예외 · 정의 조문 누락, 시점 개념 없음기각(한 축으로만)
B. LLM 추출 GraphRAG(커뮤니티 요약)넓은 질문에 요약 답관계가 모델 출력이라 재현 · 출처가 약하다(P5). 개정마다 요약이 낡는다. 오류 관계가 검색을 오염후보 추출에만
C. Neo4j + 벡터깊은 경로 · 그래프 알고리즘정본 둘(P2) · 권한 필터 세 번 구현(8.6.5) · Enterprise 필요 · 동기화 지연 · 운영 인력보류(8.5 조건)
D. PostgreSQL 온톨로지 + 하이브리드 + 폐쇄 확장정본 하나 · 권한 한 행 · 시점 · 재현 · 같은 트랜잭션4단계 이상 경로 · 전역 알고리즘은 느릴 수 있다채택

규모 감각. 법령 조회는 대부분 1 ~ 3단계에서 끝난다 — 정의 · 단서는 1단계, 준용 · 위임은 2단계 안이다. 폐쇄 요약은 이 깊이까지만 미리 펼치므로 검색 때 재귀를 돌지 않는다. 폐쇄 요약의 행 수 · 재생성 시간 · 검색 p95 는 설계 수치가 아니라 측정 대상이다(10장 골든셋).

8.2 넓은 질문 — 요약을 저장해 두지 않는다

「사규 전체에서 보안 의무는?」 같은 질문은 분류(knowledge_class) · 개념 유형(OBLIGATION) · 관계(IMPOSES)로 절을 SQL 로 모아 답한다. 문장 요약이 필요하면 그때 원본 식별자를 달아 만들고, 세대가 바뀌면 다시 만든다 — 모델이 만든 커뮤니티 요약을 원장처럼 쓰지 않는다.

8.3 검색 · 확장 SQL

관계 폐쇄 생성과 검색 질의의 설계 예시는 DB 테이블설계서 v3.22 제0AC.5 에 있다(실행 검증 전).

8.4 재순위 · 생성 · 인용 대조

재순위(교차 인코더)는 상위 12 안에서만 순서를 바꾼다 — 권한 · 시점 필터를 통과하지 않은 것을 들이지 않는다. 생성은 허용된 근거 ID 만 인용하고, 문장마다 원문 구절과 대조해 근거 없는 문장을 표시한다(FL0020026 5단계 · RL-20026-5). 인용 허락이 없는 청크는 원문 대신 식별자만 준다(R37-05).

8.5 Neo4j 를 다시 볼 조건(DB 설계방향서 v2.7 Q-6)

조건측정
ⓐ 폐쇄 요약을 두고도 4단계 이상 경로 질의가 검색 p95 목표를 넘고, 그 질의가 골든셋의 10% 이상FL0020029 검색 품질 판정의 질의 유형별 지연
ⓑ 중심성 · 커뮤니티 같은 전역 그래프 알고리즘이 업무 요구로 확정업무코드 신설 심의(FL0012027)
ⓒ 폐쇄 요약 행이 세대당 1억 행을 넘어 재생성이 색인 전환 목표 시간을 넘음index_generation.closure_count · 전환 시간

조건이 확인되면 Neo4j 는 읽기 전용 투영으로만 붙는다 — 도메인 이벤트 outbox 로 APPROVED 관계만 싣고, 정본 · 판정 · 권한 판단은 PostgreSQL 에 그대로 둔다.

9. 권한 — 원본보다 넓게 열리지 않는다
