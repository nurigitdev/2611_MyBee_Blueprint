용어 정의 — 이 문서에서 쓰는 말

「버전」은 버전, 데이터베이스의 표는 DB Table, 「중복 실행 방지」은 중복 실행 방지로 부른다(설계지시문 19.1.4).

버전 (version)문서 · 기준 · 정의가 고쳐질 때마다 매기는 번호. v1.0 → v1.1 처럼 올라간다. 예전 문서에서 「버전」이라고 부르던 것을 이 문서부터 버전으로 부른다.옛 버전은 고치지 않고 그대로 두고 새 버전을 따로 낸다. 그래야 그때 무엇을 보고 결정했는지 나중에 되살릴 수 있다.
DB Table데이터베이스에 실제로 만들어지는 표. 예) mbproj.project_request. 예전 문서에서 그냥 「표」라고 부르던 것을 DB Table 로 부른다.문서 안에서 읽으라고 그린 표(비교표 · 목록표)는 그대로 「표」라고 부른다. 둘을 섞지 않는다.
중복 실행 방지 (idempotency)같은 요청이 두 번, 세 번 들어와도 결과가 한 번 처리한 것과 똑같게 만드는 성질. 예를 들어 신청서 제출 버튼을 두 번 눌러도 신청은 하나만 생기고, 통신이 끊겨 시스템이 같은 요청을 다시 보내도 돈이 두 번 나가지 않는다.왜 필요한가 — 네트워크는 끊기고, 시스템은 답이 없으면 다시 보내고, 사람은 버튼을 두 번 누른다. 이 세 가지는 막을 수 없으므로 두 번 와도 안전하게 만든다.
중복 실행 방지 키 (중복 실행 방지 키)같은 요청인지 가리는 열쇠. 이 열쇠가 같으면 새로 처리하지 않고 먼저 처리한 결과를 그대로 돌려준다. 예) 프로젝트 신청의 열쇠는 「회사 + 신청번호 + 개정차수」다 — 같은 신청서를 두 번 보내도 신청은 하나다.열쇠는 업무적으로 뜻이 있는 값으로 만든다. 시각 · 난수 · 재시도 횟수 · 서버 이름처럼 매번 달라지는 값은 넣지 않는다. 넣으면 두 번째 요청이 「다른 요청」이 되어 중복이 생긴다.
되돌릴 수 없는 일 (non-idempotent)이체 · 발송 · 신고처럼 한 번 나가면 되돌리기 어려운 일. 이런 단계는 중복 실행 방지 키를 반드시 두고, 답이 없으면 다시 보내지 않고 조회해서 결과를 확인한다.답이 없는 상태를 「모름」으로 두고 사람이 확인하게 한다. 다시 보내는 것이 가장 위험하다.
업무코드회사의 일을 더 쪼갤 수 없는 단위로 나눠 붙인 코드. 예) FL0012001 프로젝트 신청. 사람이 하든 에이전트가 하든 같은 코드로 부른다.모든 일은 업무코드로 수행되고, 보상 · 원가 · 기록이 모두 이 코드에 붙는다.

한 줄. MyBee 의 프로젝트는 이미 Buzz 의 채널보다 구조화된 협업 단위다 — 누가(PM · PL · Member · PA · EA · 협조 PA) 무엇을(업무코드 담당 배정) 어떤 역할로(기안 · 검토 · 승인 · 실행) 어떤 순서로(선후 · 준비 조건 · 템플릿) 하는지가 원장에 있다. 여기에 없는 것은 구성원들이 그 일을 두고 함께 말하고, 에이전트의 중간 과정을 함께 보고, 그 자리에서 끼어드는 대화 층이다. 협업은 지금 배정 · 상태 · 승인 · 알림으로만 이어지고, 말은 각자 자기 IA 에게만 한다. 따라서 추가할 것은 새 협업 모델이 아니라 프로젝트 위에 얹는 대화 층(스레드 · 게시 · 멘션 · 수행 건 투영 · 스레드 개입)이며, IA 는 「프로젝트 대화에서 내가 한 말을 해석하고 내 권한 · 내 직책으로만 움직이는 개인 대리인」으로 역할을 넓힌다.

4. 빈 곳 — 협업 구조가 아니라 대화 층 · 지휘 · 유출 통제

#빈 곳왜 문제인가
G-1프로젝트에 대화 층이 없다협업은 배정 · 상태 · 승인 · 알림으로만 이어진다. 같은 수행 건을 두고 PM · 담당자 · 검토자가 각자 자기 IA 에게 묻고, 서로의 지시가 부딪히는 것을 승인 단계에서야 안다
G-2에이전트의 중간 과정을 구성원이 함께 보지 못한다상태 · 진행률 · 이슈는 보이지만 PA 의 계획, EA 의견, 협조 주고받음은 원장에만 있다. 「왜 이렇게 됐나」를 승인 순간에야 따진다(제9.4조 승인 품질)
G-3대화 속 지목(멘션)이 없다「K-IFRS EA 의견을 먼저」 「PL 님 확인」을 수행 건 위에서 할 수 없다. 모두 IA 에게 말로 풀어야 하고 IA 는 개인 문맥만 안다
G-4개입의 입구가 개인 대시보드뿐담당자 · PM 이 아닌 구성원(검토자 · PL)이 틀린 것을 봐도 수행 건 위에서 멈춤을 요청할 자리가 없다. 보고 계통(5.5.1)을 따르는 개입 경로가 데이터에 없다
G-5PA 는 사람에게 말하지 않는다(6.1.1)PA 의 계획 · 진행 · 이유가 IA 를 거쳐 사람마다 따로 요약된다. 한 프로젝트 구성원이 같은 원문을 보지 못한다
G-6대화가 원장 밖이다업무 결정이 사내 메신저에서 일어나면 근거가 수행 건에 붙지 않는다(inbound_message 는 수신 정리만)
G-7공동 편집 산출물이 없다제안서 · 설계서 초안을 에이전트가 쓰고 사람이 고치는 일이 첨부 주고받기로 된다 — 어느 줄을 누가(사람 · 에이전트) 고쳤는지 남지 않는다
G-8구성원 사이의 열람 차이를 대화가 넘을 수 있다한 프로젝트 안에서도 볼 수 있는 것이 다르다(예: 인건비 금액 노출 제한 12.7.11 · 기밀 등급). 1:1 응답을 전제한 권한 규칙(8.6)은 여럿이 보는 게시를 다루지 않는다
G-9에이전트 연쇄 호출의 상한이 없다대화에서 에이전트가 에이전트를 부르면 순환 · 폭주가 생긴다. 과업 단위 비용 상한은 있으나 스레드 단위 · 연쇄 깊이 상한이 없다

6. IA 의 협업 지휘 — 「Claude Code 에게 코딩, Codex 에게 검증」

요구. 「IA 는 에이전트이면서 협업도구 역할을 해야 한다. Claude Code 에게는 프로그램 코딩을 시키고 Codex 에게는 Claude Code 가 작성한 코드의 품질을 검증해 줘 — 라는 기능도 수행해야 된다.」 곧 IA 는 말을 알아듣는 창구를 넘어, 여러 AI 작업자에게 일을 나눠 맡기고 순서 · 반복 · 멈춤을 지휘하며 그 과정을 구성원에게 보여 주는 지휘자가 되어야 한다.

결론. 뼈대는 이미 있다. 개발 업무의 FL0003009 구현 3단계(T7 「코드 · 단위시험 초안」)와 FL0003010 코드 검토 3단계(T7 「검토 의견 초안」)가 각각 Claude Code · Codex 가 들어갈 자리이고, 「변경 요청이면 구현으로 되돌림」(EXT:FL0003009) · 빌드 · 단위시험 · 정적 분석 · 보안 게이트(FL0003011 · 012)도 있다. 비어 있는 것은 네 가지다 — ① IA 가 「누구에게」(지정 작업자)와 「어떤 순서 · 몇 번까지」를 해석해 협업 계획으로 만드는 기능 ② 외부 AI 작업자(Claude Code · Codex · goose …)의 등록부와 연결 통로 ③ 작업자를 가두는 샌드박스 작업 세션 ④ 작성자 ≠ 검증자 · 반복 상한 · 데이터 반출 같은 규칙. IA 는 지휘하고, 수행 책임과 원장은 프로젝트의 PA, 바깥 호출은 TA, 통과 판정은 도구 · 규칙과 사람 검토자가 맡는다.

13. 위험과 남은 결정

#결정할 것선택지 · 권장
D-16.1.1 PA 의 「사람에게 직접 말하지 않는다」를 좁힐지권장: 좁힌다 — 게시는 허용, 입력은 IA 경유(6장). 좁히지 않으면 프로젝트 대화에서 PA 글이 IA 요약으로만 보여 구성원이 같은 원문을 보지 못한다
D-1a프로젝트 밖 대화(팀 · 1:1)를 대화 층에 넣을지권장: 넣지 않는다 — 업무는 모두 프로젝트(운영 프로젝트 포함)에 담기므로(5.1.3) 대화 층도 프로젝트 단위로 충분하다. 사적 대화는 기존 사내 메신저
D-2대화 기록을 어디에 둘지기록은 필수(C-8). 권장: 게시 원장(mbcollab.post)에 전부 남기고 해시 사슬 감사에 포함, 트랜잭션 원장에는 넣지 않는다 — 업무 결정은 수행 · 승인이 원장에 남긴다
D-2a대화 보존 기간 · 맥락 버전을 만드는 시점권장: 보존 기간은 업무 원장 보존 기간과 맞추되 개인 1:1 대화는 본인 요청 파기를 허용(맥락 버전 함께). 맥락 버전은 스레드가 N개 게시 · T 시간을 넘거나 24시간 쉬었을 때 — 값은 운영 정책 데이터
D-3에이전트 간 A2A 메시지 공개 범위권장: 기본 비공개 · 프로젝트 정책으로 공개 등급(계획 · 진행 · EA 의견)만 미러
D-4외부 AI 를 대화 참여자로 받을지 · 언제권장: 6단계 · 개발 영역(D01 ~ D03) 프로젝트부터 · 읽기 + 게시만(일을 맡기는 작업자는 3단계 · D-7 ~ D-9)
D-7IA 가 외부 AI 를 직접 부르게 할지권장: 부르지 않는다 — IA 는 지휘(계획 · 대화 · 중계), 호출은 TA, 수행은 PA. 사용자 눈에는 같고, 반출 통제 · 원장 · 비용이 한 통로에 모인다
D-8작업자가 작업 브랜치에 직접 커밋하게 할지권장: 작업 브랜치만 허용(FL0003009 4단계 「개발자 구현 · 커밋」을 「개발자 확인」으로) · 병합은 언제나 사람 승인
D-9처음 허용할 업무 · 자료 범위권장: D03 응용 SW 의 INTERNAL 등급 저장소부터, CONFIDENTIAL 은 가명화 확인 뒤, SECRET · 개인정보 · 미공개중요정보 · 고객 제공 자료 · 핵심기술은 사내 모델만

D-6「대화」를 의도 종류로 둘지권장: 둔다 — 프로젝트 대화 발화의 대부분이 과업이 아니므로 범위 밖과 섞으면 해석 품질 측정이 흐려진다
