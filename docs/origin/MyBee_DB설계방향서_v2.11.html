용어뜻
평면(plane)데이터의 성질과 쓰임이 같은 것끼리 묶은 저장 구획. 본 설계는 값·구조·의미·사건의 4개 평면으로 나눈다.
정본(正本)그 데이터의 진짜 값이 있는 유일한 테이블. 값·구조·사건 평면은 논리 구분이며 PostgreSQL 안에 함께 있다. 의미 색인과 게시 스냅샷은 파생본이다.
저작(著作) 구조사람 또는 에이전트가 설계·편집해서 만드는 구조 — 조직도, BOM, 업무코드 체계, 권한 구조. 편집이 곧 업무인 데이터.
발생(發生) 구조업무 실행이 결과로 남기는 관계 — 로트 계보, 수행 선후, 승인 의존, 파생 계보. 트랜잭션과 함께 태어나는 데이터.
게시(揭示) 스냅샷구조 평면에서 편집·검증을 마친 구조를 버전 번호와 함께 값 평면에 옮겨 적은 판정용 사본. 판정은 이것만 읽는다.
투영(投影)정본 테이블에서 만든 조회용 뷰·색인·요약. 원본 행을 다른 DB로 복제하지 않는다.
중복 실행 방지 키같은 요청이 두 번 와도 한 번만 실행되게 하는 열쇠 값.
RLS(행 수준 보안)질의 결과를 행 단위로 걸러 자기 테넌트만 보이게 하는 기능.
사건 평면업무 변경을 추가전용으로 적는 기록. 감사 재현과 파생 색인 재구축의 원천이다.
도구 계약에이전트가 저장소에 닿는 유일한 통로. 에이전트는 SQL·그래프 질의를 직접 쓰지 않고, 평면을 아는 도구를 호출한다.

기존 설계의 일곱 원칙을 PostgreSQL 단일 정본 구성에 적용한다.

원칙(지시문 근거)v2.4 구성이 지키는 방법
P1 판정은 결정론 · 닫힌 실패
(P-06 · 6.6.4 · 13.3)		판정 경로의 구조 입력은 승인된 게시 버전만 허용한다. 초안 조회·벡터·LLM 결과는 판정 입력이 아니다. 게시본이 없거나 버전이 맞지 않으면 차단한다.
P2 데이터마다 정본 하나
(원장 소유 12.2)		구조·값·사건 모두 PostgreSQL 표준 테이블에 정본을 둔다. 각 개체와 관계의 원본 테이블을 하나로 정하고, 게시 스냅샷·조회 뷰·요약 인덱스는 파생 조회 계층으로 카탈로그에 명시한다.
P3 부작용 단일 통로 · 중복 실행 방지
(6.5 · 7.5)		원장과 게시 기록은 PostgreSQL 트랜잭션으로 확정한다. 게시 실행 기록(policy_publish_run · definition_bundle)에 중복 실행 방지 키와 원본 버전을 묶고, 외부 부작용은 TA 경유 규약을 따른다.
P4 테넌트 격리 · 안전한 실패
(12.5)		테넌트 소유 구조 테이블과 관계 테이블에도 tenant_id · RLS 를 적용한다. 복합 FK 와 조회 술어에 tenant_id 를 포함해 테넌트 간 연결을 차단한다. 플랫폼 공통 자료는 별도 권한으로 읽게 한다. 재귀 경로 조회도 테넌트 경계 음성 시험을 통과해야 한다.
P5 기록 재현
(15.3 · 3선 감사)		판정 재현에는 게시 버전과 입력 해시를 사용한다. 초안·게시·취소의 변경 이력은 사건 평면에 남겨 당시 구조의 결정 근거를 재현한다.
P6 운영 중 무변경 확장
(12.1.1)		기존 표의 ext jsonb · mbmeta 카탈로그를 따르며, 새 관계 유형은 정식 테이블·제약 또는 승인된 카탈로그 확장으로 정의한다. 조회 뷰·파생 요약의 변경도 배포 세대를 기록한다.
P7 에이전트 실행 · 사람 승인구조 편집도 업무다. 조직 개편·BOM 개정·권한 변경은 에이전트가 초안을 만들 수 있고, 게시 전에 사람이 승인한다(작성자≠승인자, 위험 C 두 사람 규칙).

3.2 구조 평면 — PostgreSQL 표준 테이블 정본 (47 DB Table)

조직도(mbcore.org_unit · employee_org_assignment), BOM(mbdev.bom_master · bom), 업무코드·스킬·도구, 권한·위임, 메타데이터 상관관계의 기존 34표를 그대로 정본으로 둔다. 개체 행과 관계 행은 명시적 PK·FK·유효기간·승인 상태를 가지며, 임직원·품목·회사 속성도 기존 값 테이블이 소유한다. 다형 관계(entity_link 등)는 대상 종류와 식별자의 존재·테넌트 일치를 게시 전 검증한다.

구조 조회의 확정 구현.
업무별 FK 조인, WITH RECURSIVE 및 CYCLE 로 조직·BOM·위임 경로를 조회한다. 대규모 역방향 파급은 승인 버전별 요약 또는 폐쇄 관계 인덱스를 파생해 성능을 맞춘다. 원본 관계 행과 조회용 파생본의 소유권을 카탈로그에 기록한다.

게시 절차: ① 초안을 업무별 정본 테이블·개정 이력에 기록하고 판정에서는 숨김 ② FK·테넌트·유효기간·고아·순환·SoD·파급 검증 ③ 작성자와 다른 사람의 승인 ④ 동일 트랜잭션에서 스냅샷·게시 실행 기록·현재 버전 포인터·사건 기록을 확정 ⑤ 시행일부터 새 버전 조회. 실패하면 전체 롤백한다. 되돌림은 이전 버전의 새 게시 기록으로 남긴다.

-- candidate_edges: 선택한 초안 BOM + 기준 시각에 유효한 다른 품목 BOM 의
-- (tenant_id, parent_item_code, child_item_code) 읽기 전용 관계 집합
WITH RECURSIVE walk(tenant_id, root_code, item_code, depth) AS (
  SELECT tenant_id, parent_item_code, child_item_code, 1 FROM candidate_edges
  UNION ALL
  SELECT w.tenant_id, w.root_code, e.child_item_code, w.depth + 1
  FROM walk w JOIN candidate_edges e
    ON e.tenant_id = w.tenant_id AND e.parent_item_code = w.item_code
  WHERE w.depth < :depth_limit
) CYCLE item_code SET is_cycle USING path
SELECT 1 FROM walk WHERE is_cycle LIMIT 1;

candidate_edges 는 현행 mbdev.bom_master 의 bom_no·parent_item_code·revision·status 와 mbdev.bom 의 bom_no·child_item_code 를 조인해 만든 질의용 관계 집합이다. 초안 선택·유효기간·여러 품목의 개정 충돌 해소 규칙을 먼저 확정해야 한다. 깊이 한도 초과는 안전한 성공이 아니므로 게시를 차단한다. 파생 요약은 같은 승인 버전의 재귀 SQL 결과와 일치해야 한다.

3.3 구조 평면의 조회 구역 — 발생 구조 (25 DB Table, 정본은 값 평면)

로트 계보·파생 계보·수행 선후·승인 의존·프로젝트 계층·연결결산 구조·추적성은 트랜잭션이 낳는 관계다. 생산 실적과 로트 계보는 같은 PostgreSQL 트랜잭션에서 확정된다. 리콜 파급·SoD 위반 경로 탐지·승인 무효화 반경은 이 원본 표를 재귀 SQL로 조회하며, 필요하면 파생 요약을 만든다.

3.4 의미 평면 — pgvector (9 DB Table): 원문 정본과 같은 집

의도 카드·발화 예문·조문 임베딩·기억 색인·의미 캐시. 전부 파생 데이터이며 원문 정본은 값 평면에 있다. 전용 벡터 DB 를 두지 않는 이유는 v1.0 그대로 — 권한 사전 필터(8.6.5)를 임베딩과 같은 행에서 RLS+WHERE 로 걸어야 하기 때문. 법규 저장소도 기존 벡터 DB 전제를 걷어내고 여기서 신규 구축한다(키워드 tsvector/pg_bigm + 벡터 HNSW 의 RRF 합산 + 교차 인코더 재순위, 판정 입력은 조문 식별자 결정론 조회만 — v1.0 2.3a 결론 승계). 에이전트 기억 3층(개인·조직·규칙)은 벡터 색인(찾기) + 값 평면 원문(읽기) + 사건 평면(언제 무엇을 배웠나)의 3평면 합작으로 구현된다.

3.5 사건 평면 — 추가전용 파티션 (15 DB Table): 동기화·재구축·재현의 단일 원천

v1.0 에서 「이력 파티션」이라 불렀던 것을 1급 평면으로 승격한다. mbaudit.domain_event 가 중심이다 — 값 평면의 모든 업무 변경, 구조 평면의 모든 게시, 의미 평면의 모든 재색인이 사건으로 남고, 의미 색인·파생 요약의 재구축은 사건 재생으로 이뤄진다. 정본 관계 행은 업무 트랜잭션이 소유한다. 시각 내장 식별자 + 범위 파티션 + 해시 체인 + 외부 고정 그대로. 에이전트 중심 시스템에서 이 평면의 무게가 커지는 이유: 에이전트의 학습·평가·판정 재현이 전부 「그때 무슨 일이 있었나」를 다시 읽는 일이기 때문이다.

D. 권장 — PostgreSQL 안의 온톨로지 + 출처 있는 관계 + 하이브리드 검색 + 관계 확장조문 구조 관계는 파서가 결정론으로 뽑고(정의 · 단서 · 준용 · 위임 · 인용), 업무 관계만 사람이 확인한다. 형태소 · 벡터 검색을 권한 칸과 같은 행에서 거른 뒤 RRF 로 합치고, 세대별 관계 폐쇄 요약으로 함께 읽을 조문을 붙인다. 시점 · 권한 · 재현이 한 트랜잭션 안에 있다다단계(4단계 이상) 탐색과 전역 그래프 알고리즘은 느릴 수 있다 — 폐쇄 요약으로 막고, 측정으로 확인한다채택

한 번의 질문이 지나가는 길. ① IA 가 의도를 해석한다 → ② 권한 사전 필터(RLS + 기밀 등급 · 열람 범위 · 기준일)를 청크 행에 건다 → ③ 형태소(mecab 계열 tsvector) 30 · 벡터(pgvector HNSW, 0.8 반복 스캔) 30 후보를 RRF(k=60)로 합친다 → ④ 상위 조각의 조문 · 절에서 관계 폐쇄 요약을 따라 「항상 함께 가져올」 예외 · 정의 조문과, 질문 유형이 요구하면 준용 · 위임 · 상위 법령 · 연결 사규를 덧붙인다 → ⑤ 덧붙인 것도 다시 권한 필터를 거친다 → ⑥ 교차 인코더로 재순위 → ⑦ 근거 묶음(자산 · 버전 · 해시)을 굳혀 생성 · 인용 대조. 검색 기록(retrieval_log)에 세대 · 확장 경로 · 기준일이 남고 판정 사용은 false 다. 판정은 조문 · 절 식별자의 결정론 조회만 한다(13.3 · R37-04).

음성 · 화상 매체 v2.10DB 밖 — 실시간 매체 서버(SFU)가 나른다. 원장에는 회의 머리 · 참여 · 녹음 동의(mbcollab.huddle · huddle_participant, 값 · 사건)만매체 흐름은 초당 수십 KB 의 연속 데이터라 DB 가 다룰 것이 아니다. 동의 · 기한 · 요약만 원장이 책임진다
녹음 원음 · 음성 메모 · IA 음성 입력 원음 v2.10국내 객체 저장소 — DB 에는 위치 · 해시 · 등급 · 기한만(media_recording · voice_utterance, 사건). 기한이 지나면 원음만 지우고 해시는 남긴다원음은 크고 민감하다. 삭제 가능해야 하고, 지운 뒤에도 무엇이 있었는지는 해시로 증명한다

부하 가정. 1,000 테넌트 × 활성 사용자 · 에이전트 게시를 합하면 게시는 원장 행보다 한 자릿수 이상 많다. 그래서 1단계부터 ① 월 파티션과 보존 기간(협업 운영 정책)에 따른 분리 보관 ② 게시 목록은 스레드 · 게시 번호 순서 색인 하나로 ③ 통합 검색 색인(형태소)은 게시와 같은 행 · 권한 사전 필터 ④ 실시간 전달은 DB 폴링이 아니라 전달 계층으로 한다. 그래프 DB · 별도 메신저 DB 를 들이지 않는다 — Buzz 도 Postgres(사건 · 전문 검색) + Redis(구독 · 접속 상태) 구성이다.

4. 판정 경로 — 바뀌지 않는 한 가지

판정(Trust Agent · VA · 착수 게이트 · 준비 조건)은 게시 버전의 값 평면만 읽고 값 평면에만 쓴다.
구조 탐색 질의는 편집·분석 도구에서만 호출한다. 판정의 구조 입력은 게시 스냅샷이다. 이렇게 가르면: ① 같은 입력·같은 정책 묶음이면 같은 답(P1) — 편집 중 구조가 판정에 새어들 수 없다 ② 판정 재현(P5)은 게시 버전 원장과 입력 해시로 가능하다 ③ 구조 분석용 파생 요약이나 벡터 검색 장애 시에도 이미 게시된 구조로 업무 실행은 계속된다. 다만 원본 PostgreSQL 장애는 공통 장애이므로 HA·복구 목표를 별도로 충족해야 한다.

6. PostgreSQL 내부의 무결성·게시 규약

값·구조·사건의 원본 테이블이 같은 PostgreSQL 안에 있으므로 가능한 관계는 FK 로 강제한다. 다형 참조와 버전 게시에는 다음 규약을 더한다:

규약내용
식별자·참조기존 UUIDv7/식별자 규약을 유지한다. 가능한 관계는 FK 로 강제하고 테넌트 소유 간선은 양 끝의 tenant_id 일치를 보장한다. 다형 관계는 종류별 검증 함수와 게시 게이트에서 존재·권한을 확인한다.
게시 규약저작 상태와 승인 상태를 분리한다. 게시 실행 기록의 중복 실행 방지 키, 원본 버전, 게시 해시, 승인자, 시행시각을 묶는다. 게시본과 현재 버전 포인터의 갱신은 한 트랜잭션이어야 한다. 게시 없는 초안은 판정에서 보이지 않는다.
사건 규약정본 변경·게시·재색인을 사건으로 기록한다. 의미 색인과 선택적 경로 요약만 사건으로 갱신하며, 원본 관계를 별도 DB에 재생하지 않는다. 파생본 지연과 기준 시각을 도구 응답에 표시한다.
대사 규약일 1회 게시 해시·버전·원본 관계 수·파생 요약을 대조한다. 어긋나면 판정에는 마지막 유효 게시본을 유지하고 파생본을 원본에서 재생성한다.

8. 확정 기술 — PostgreSQL 표준 테이블과 재귀 SQL

확정: 값·구조·사건의 정본은 PostgreSQL 표준 테이블이다. 구조 경로는 FK 조인, 재귀 CTE, CYCLE, 필요한 파생 요약으로 조회한다. Neo4j·TypeDB·Apache AGE 및 별도 그래프 조회 제품은 구축 범위에 두지 않는다.
