2. 주제별 요약

2.1 BOM 자리별 대체 · 로트 단위 자동 대체 v5.14 · 제12.9조

요구 「대체 부품은 원본의 단종 · 납기 지연 때 자동으로 로트 단위로 쓸 수 있어야」. 설계 무엇으로 바꿀지는 설계가, 언제 바꿀지는 규칙이, 바꾼 사실은 로트가 기억한다.

항목내용
승인 단위품목이 아니라 BOM 자리마다 — 같은 부품도 제품 · 자리에 따라 인증 · 펌웨어 · 열 설계 영향이 다르다. 작성자 ≠ 승인자, 단종 부품은 대체로 게시 불가
자동 범위설계가 자리마다 정함 — 단종 · 납기 지연(허용 일수) · 둘 다 · 자동 불가. 범위 밖은 제안으로 사람에게
로트 단위한 작업지시 · 한 자리에는 원본이나 대체 하나만 — 원본이 로트 몫을 못 채우면 로트 전량 대체
판정 · 확정MRP 안에서 누적 순소요로 판정(계획) → 작업지시 발행이 확정. 착수 뒤에는 바꾸지 않음
조회EBOM · MBOM 다단 전개와 대체 경로는 재귀 SQL, 순환은 CYCLE 로 멈춤

산출: BOM 대체부품 · 로트 자동 대체 설계서(S-22, 현재 v1.3 — 09-30 용어 규칙 재적용) · DB Table +2 · 규칙 R35 · 인수 기준 A-41.

2.2 MPS → MRP 순서 v5.15 · 제12.10조

요구 「생산계획 대비 부품 재고 · 납기를 감안한 생산계획은 MRP 에서 해야 하지 않나?」. 설계 완제품 일정은 MPS, 부품 계산은 MRP 가 한 번, 지시는 그 결과를 근거로.

항목내용
계산의 자리BOM 전개 · 재고 차감 · 순소요는 MRP 실행 한 곳에서만. 작업지시 · 구매요청은 근거 계획 오더를 가진다
MPS완제품만 계산 · 능력 부하 검토는 MPS 확정 앞
MRP확정된 MPS 버전으로만 · 입력은 같은 기준 시각 · 하위 단계(LLC) 순서 · 입력 해시로 재현(같은 입력이면 재계산 안 함)
계획 오더한 건은 구매요청 또는 작업지시 하나로만 전환 · 페깅(근거 MPS 줄 · 상위 오더 · BOM 자리)
부족필요일 안에 못 채운 소요는 예외로 MPS 확정에 되돌림 — 예외가 남으면 작업지시 발행 불가

업무코드 수는 그대로(이름 3건 교체) · DB Table 547 → 549 · 규칙 R36 · 인수 기준 A-42.

2.4 IA 협업 — 에이전트이면서 협업 도구 v5.17 · 제12.13 · 12.14조

요구 「IA 를 Block Buzz 처럼 사람 · AI 협업 도구로」 → 「프로젝트는 이미 멀티 에이전트 · 여러 사람 협업 단위」 → 「대화를 기록해 이어 가기」 → 「Claude Code 에 코딩, Codex 에 검증」 → 「외부 유출 규제」 → 「내외부 멀티 협업 검증」 → 「외부 사람과는 메일로도」 → 「권고안(D-1 ~ D-15) 모두 반영」.

층설계
대화 층새 공간을 만들지 않고 프로젝트 = 공간, 수행 건 = 스레드. 스레드 8종 · 게시 · 멘션 · 개입(담당 · PM · 계통만 효력) · 반응(효력 없음) · 공동 문서 · 수행 카드 투영(PF-11)
기록 · 이어 말하기사람 입력과 에이전트 응답 원문 전부(IA 1:1 포함) · 감사 해시 사슬 · 맥락 버전은 요약일 뿐 근거가 아니고 이어 말할 때 원장 현재 값을 다시 읽는다
지시의 길사람 글은 발화자 본인 IA 만 지시로 해석 · 남의 글 · 게스트 글 · 메일은 데이터 · PA · EA 는 서명해 게시 가능 · IA 는 외부를 부르지 않음(호출 TA · 수행 PA)
협업 지휘IA 가 「A 작성 · B 검증」을 협업 계획 초안으로 → PA 확정. 외부 AI 작업자(Claude Code · Codex)는 EA 「프로그램 작성」 백엔드 · TA 커넥터 · 샌드박스 · 작업 브랜치 커밋만 · 작성자 ≠ 검증자 · 반복 상한 3 · 병합은 사람
외부 협업 · 메일외부 사람은 초대 승인된 게스트(계정 없이 메일 가능) · 스레드별 토큰 회신 주소 · SPF/DKIM/DMARC · 대조 실패는 보류함 · 담당 IA 대리 해석 → 요청 카드 · 메일 회신은 일정 · 수령 · 단순 의견만, 확정은 확인 링크 · 전자서명 · 외부끼리 3자는 승인
유출 통제세 번 막는다 — 계획(업무별 외부 위임 등급) · 전송(TA 반출 관문: 반출 허용표 + 결정론 내용 검사, 보류는 사람 승인) · 사후(반출 기록 · 위반 판정). 처음 범위는 D03 사내 공개 저장소

2.6 음성 · 모바일 협업 v5.19 · 제12.15조

계기 「MyBee IA · Slack · Buzz 비교」 — 음성 허들 · 모바일 대화가 설계에 없었다. 원칙 글 대화의 원칙을 그대로, 업무코드는 늘리지 않음(운영 값 · 모바일 기준은 FL0013052).

항목설계
음성 회의스레드 안에서 · 매체는 LiveKit(자체 호스팅), 원장엔 머리 · 참여 · 동의 · 요약만 · 녹음은 참여자 전원 동의 · 전사는 사내 엔진 · 화자는 접속 신원 · 전사는 근거 아님
음성 입력해석까지만 — 화면 확인 문장이 있어야 과업 · 제출 · 개입, 승인은 음성으로 받지 않음 · 원음 해시 · 전사 · 확인 문장 보존
모바일무결성 증명 뒤 활성 · 기밀 등급 × 기기 등급 기준(없으면 거부) · 고위험 승인 생체 재인증 · 푸시 본문 최소화(국외 사업자) · 원격 삭제 · 오프라인은 작성까지
사람 보호업무시간 밖 푸시 기본 끔 · 회의 참여 · 전사 · 알림은 평가 · 근태 자료 아님 · 발화 시간 · 접속 상태 · 위치 기록 안 함
